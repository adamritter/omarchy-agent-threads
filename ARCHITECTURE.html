04 / Reload model

Reload the smallest safe graph

Most saves stay inside the running Quickshell process. The manifest boundaries preserve the panel, providers, stores, windows, and service state.

Choose scope from the file’s role, not from how visually large the edit feels.

01

Exact manifest boundary file?

Call reloadEntryPoint() on every live widget instance. Preserve long-lived state and replace only the declared loader.

NARROW HOT RELOAD
02

Existing imported QML or JavaScript?

Use the automatic in-process QML graph reload. If the result is missing, run ./scripts/reload-plugin.

GRAPH RELOAD
03

New or renamed QML component?

Try graph reload first. One complete shell restart is valid if Qt’s imported-directory cache cannot discover the new name.

CACHE EXCEPTION
04

Startup, shutdown, or stuck runtime?

A complete restart is appropriate for lifecycle reproduction, socket or child-process recovery, and explicit release smoke tests.

FULL RESTART

Panel ownership is a protected seam. Run tests/panel-render.test before and after changes to Panel.qml ownership, window bindings, overlays, or list wiring. Never run the live Wayland mode during an active session.

06 / Change discipline

Six rules keep the graph honest

A useful boundary hides implementation details, enforces ownership, or creates a real lifecycle and test seam. More files alone do not improve architecture.

Trace inward once

Start at the visible behavior, cross one domain API, and stop at one owner.

Open one provider chain

Use the common library only for shared contracts; otherwise load only the selected provider.

Extract the decision

Put deterministic branching in logic/ before adding it to a QML adapter.

Keep one truth

Do not duplicate derived values as mutable state to shorten a binding chain.

Delete the bypass

Redirect callers and remove obsolete aliases, routes, and forwarding-only components.

Update the map

Change this field guide and ARCHITECTURE.md with every public boundary change.
